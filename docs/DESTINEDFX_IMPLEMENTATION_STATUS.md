## Nov 20 code review and lifecycle hardening (latest CI pending for head 7c7227e)

- **Bridge Linux-host enrollment:** EPHEMERAL Codespaces with verified per-user slot isolation can enrol DEMO only. LIVE is rejected before managed-account credential storage or worker-job creation. Regression tests cover allowed DEMO enrollment, LIVE refusal, and unready isolation.
- **Codespaces first-run worker check:** now inspects the exact isolated slot-worker process path/arguments under `/proc`, avoiding the legacy worker mismatch and self-matching `pgrep` issue.
- **Xvfb ownership continuity:** repeated `vnc-up.sh` preserves the `started` marker only when prior PID and managed-process record agree; incomplete or mismatched prior ownership fails closed.
- **Installer marker lifecycle:** a shared `scripts/linux-host/finalize-mt5-install.sh` now requires verified MetaQuotes installer provenance, terminal + MetaEditor files, and a successful isolated compile of the EA before writing `installer-verified`. Headless post-create uses it; the GUI fallback tells the owner to run it after completing the wizard. This compile acceptance does not prove the terminal can authenticate to a broker or that it opens cleanly without an owner-observed debugger dialog.
- **Process shutdown identity hardening:** Codespaces-managed VNC, user worker and root host-agent process records now bind PID, kernel start ticks, effective UID, resolved executable and the complete argv. Shutdown pins the PID with Linux pidfd, revalidates identity after opening it, and sends SIGTERM only; no PID-only legacy record is upgraded, and unresponsive processes are not force-killed. Root reads are protected against user-forged records and symlink/path replacement by owner-UID checks and descriptor-based reads.
- **VNC authentication verification:** x11vnc uses a private `-passwdfile` first-line password file (not the distinct encrypted `-rfbauth` format). The Codespaces self-check now performs a real local RFB VNC challenge/response against port 5900 and confirms loopback-only listeners; it does not claim a browser-to-noVNC websocket handshake or MT5 terminal startup.
- **GitHub authorization revocation:** the Bridge proxy now calls the GitHub App grant-revocation endpoint, rather than the single-token endpoint, so a confirmed result represents revocation of the app authorization grant. Android also fails closed unless both current and backup broker-safety reports are explicitly safe with no reasons.
- **Android account freshness:** Connected Account balance/equity/free-margin are withheld as STALE unless the account-bound EA heartbeat and at least one terminal quote are within 15 seconds.
- **Latest CI at the previous source head:** all four required workflows were green on `1126cfc4` (Build APK, Codespaces deployment diagnostics, MetaQuotes installer verification, Wine guard). The additional RFB handshake and process-record ownership hardening is on `7c7227e` and its matching CI is still pending; this older green result does not validate the newer files.

## Execution workers

- **Windows worker:** has per-job terminal copies, per-job data directories, process ownership checks, restart/revocation handling, signed reservation claims, and final process-evidence finalization integrated with the bridge.
- **Codespaces Linux slot worker:** provisions one non-login Unix identity per pairing, a private per-job Wine prefix and portable MT5 tree, a private Xauthority cookie, a dedicated Xvfb display, separate logs/manifests, and CPU/RAM-bounded capacity. A pairing may have only one active terminal; re-enrolment is blocked until the previous worker-confirmed revoke completes. The root host agent verifies the account/UID, home and directory ownership/modes, Xvfb identity, and the live MT5 process PID/start-time before the Bridge accepts reservation and final process evidence. New Linux slot provisioning remains DEMO-only; LIVE remains blocked.
- **Legacy owner-managed systemd worker:** `linux-worker.py` is still the single-terminal service path. It is not the multi-user slot implementation and must not be treated as providing per-user isolation. The Codespaces launcher uses `linux-slot-worker.py` with `linux_isolation.py` and the root host agent.
- **Code-level acceptance:** Python regression tests cover distinct identities and terminal trees for FBS, Exness, HFM and Deriv DEMO pairings; duplicate-terminal rejection; unreadable-marker fail-closed behaviour; loopback-only root-agent routing; and atomic terminal-marker updates. On PR head `33b5bd91e100dc2d40483e23fa223f4d37538677`, the Build APK Python job reported 48 Linux host/isolation/worker tests and 65 Bridge tests passing, and the Wine guard regression workflow passed. These are CI/offline tests, not proof of real OS-account creation or MT5 runtime readiness on the owner's host.

## Android-controlled Codespaces lifecycle (implemented in source; CI and owner acceptance pending)

- **Android GitHub App authorization:** the Bot workspace now includes GitHub App Device Flow using Custom Tabs and the public App Client ID. It requests `offline_access`; expiring user access tokens and rotating refresh tokens are stored in the existing Android Keystore-backed encrypted preferences. The App client secret and PAT are not embedded in the APK. The UI allows local token clearing and a server-side revoke attempt.
- **Permissions:** Codespaces metadata: read is required to list/read Codespaces. Codespaces lifecycle admin: write is required for start/stop. The owner must enable GitHub App Device Flow. See [GitHub App device flow](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app) and [GitHub App REST permission matrix](https://docs.github.com/en/rest/authentication/permissions-required-for-github-apps).
- **Discovery and lifecycle:** the Android client paginates `GET /user/codespaces`, selects only the exact repository and branch, fetches and revalidates the API-returned Codespace before every start/stop, and never hard-codes a Codespace name. START HOST and STOP HOST are separate from Bot START/STOP/PAUSE actions.
- **Boot path:** `.devcontainer/devcontainer.json` now uses `postStartCommand` to call `scripts/host/destinedfx_trigger_host.py start_all`. The adapter reuses the existing `deploy/codespaces/host_controller.py`, `start.sh`, and `stop.sh` paths; it does not launch `gui.sh` and does not implement a second MT5 startup path. Its process checks record/verify PID, start ticks, UID, executable and argv.
- **Bridge safe-stop:** the Bridge exposes `POST /v1/app/host/shutdown-safe` and `POST /host/shutdown-safe` aliases. It owner-authenticates, blocks new commands, checks broker/EA/position/order/unresolved-command state and verifies an online SQLite backup/recheck. Android requests the GitHub Codespaces STOP only after `PREPARED` + `backup_verified=true`. If state is unsafe, unknown or ambiguous, it leaves the host running and does not close trades. The Bridge API acknowledgment is a safe preflight/backup acknowledgment; it is not an assertion that the whole VM has completed a local shutdown.
- **Status/UI:** the host panel reuses the existing five-second Bridge polling loop, displays GitHub lifecycle state separately from Bridge/host-agent readiness, requires verified isolation plus fresh EA/terminal evidence before showing ACTIVE, and displays account balance only when the snapshot and broker quote are fresh (15-second threshold); otherwise balance is labelled STALE.
- **Usage guard:** Android and the host adapter maintain device/host-local start/stop estimates, show daily minutes and monthly core-hours, block new Android starts after the 90-minute daily target or below 10 estimated monthly core-hours, and count Codespace boot time. This is an estimate, not GitHub's authoritative billing meter; sessions before tracking began or stops from other devices can be missed. The 120 core-hour/month GitHub Free allowance and two-core multiplier must be checked against [GitHub billing](https://github.com/settings/billing). A 20-minute idle allowance is part of—not added to—the 90-minute daily target.
- **Revocation:** the optional Bridge revoke proxy calls GitHub's token revocation endpoint only when the owner has configured `CODESPACES_GITHUB_CLIENT_ID` and `CODESPACES_GITHUB_CLIENT_SECRET` as private environment secrets. No secret is shipped to Android. Without those settings the app directs the owner to GitHub Settings. Local token clearing is not a claim of remote revocation.
- **CI:** the latest changes are committed on PR #16; GitHub Actions is running for the newest head. Do not claim a passing build until all relevant workflows finish green.
- **Not owner-accepted:** the GitHub App has not yet been configured by the owner; no physical phone install/UI test, actual Codespace start/stop test, two-user concurrent MT5 runtime acceptance, or genuine FBS/Exness/HFM/Deriv DEMO lifecycle has been performed. The host remains EPHEMERAL/DEMO-only and LIVE remains blocked.

## Live Codespaces two-user runtime acceptance

The offline CI suite validates the isolation code and its failure guards; it does not establish that two real MT5 terminals are running as separate operating-system users on the owner's Codespaces host. A read-only runtime audit is now provided at `scripts/linux-host/accept_two_user_runtime.py`.

After two different broker pairings have each been provisioned as DEMO and have reached `READY` on the actual Codespaces host, run from the checked-out repository:

```bash
sudo -E python3 scripts/linux-host/accept_two_user_runtime.py --expected-users 2
```

The script fails closed unless it can verify at least two READY slot manifests; distinct pairing/job IDs, Unix usernames and UIDs, Wine prefixes, portable terminal trees, Xauthority files, Xvfb displays and real process identities; root-agent reservation checks; per-slot ownership and restrictive permissions; denial of cross-user Xauthority reads and writes; removal of startup credential files; and a healthy loopback host-agent report. It emits sanitized JSON and does not print account identifiers or credentials.

This audit is strictly read-only: it does not create users, launch or stop MT5, revoke pairings, modify host files, or submit trades. It must be run on the real Codespaces host while both DEMO sessions are running. A passing unit test or hosted GitHub runner cannot substitute for that live-host result. Android API 34 instrumentation and the captured Bot UI screen evidence remain separate gates; screenshots alone do not prove MT5 Android feature parity.
