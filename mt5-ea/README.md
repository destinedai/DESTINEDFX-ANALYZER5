# DestinedFX MT5 EA (bridge v1)

`DestinedFXTraderEA.mq5` is a real MQL5 Expert Advisor using `CTrade` for orders and outbound HTTPS `WebRequest` calls for the documented DestinedFX bridge v1. It is not a port of every Android signal, strategy, or risk feature and does not implement an undocumented protocol.

## Exact strategy scope

The only supported strategy is a deterministic **ICT Silver Bullet subset** (`ict-silver-bullet`): scan configured symbol/timeframe pairs on a timer; require a recent three-candle directional FVG (up to 15 closed bars old), current price within `max(0.25 × ATR(14), 2 × spread)` of the FVG midpoint/CE, and UTC London/NY killzone windows 07:00–09:00, 13:30–15:30, or 18:00–20:00. It additionally requires a prior local swing sweep with close-back rejection and a same-direction displacement candle whose body is at least 0.5 ATR. The sweep/displacement thresholds and local swing interpretation are conservative implementation choices, not a claim of parity with the app's complete ICT analysis. The app's source describes a killzone-specific liquidity sweep and 1m–5m FVG displacement model, CE entries, and 1:2 minimum RR; the app's plan specifically requires a recent unfilled directional FVG and the CE distance tolerance above.

No SMC confluence scoring, higher-timeframe alignment, news filtering, full liquidity-pool/equal-high-low analysis, other registered strategies, or app-grade signal invalidation is implemented. The EA rejects strategy configuration other than `ict-silver-bullet`.

## Installation and pairing

1. Use a **demo account first**. Automated trading can lose money; there is no profitability guarantee. Verify symbol suffixes, contract specifications, stop/freeze restrictions, and behavior on your broker before considering any live use.
2. Copy the `.mq5` file into the terminal's `MQL5/Experts` directory, open it in MetaEditor, compile, then attach it to any chart. It scans its configured symbols/timeframes rather than trading only the chart symbol.
3. In MT5, open **Tools → Options → Expert Advisors → Allow WebRequest for listed URL** and add the exact HTTPS bridge base URL (for example, the deployment URL `https://bridge.example`, without a path). The URL must be the actual deployment host, not this example. Enable Algo Trading and permit EA trading.
4. Set `InpBridgeBaseURL` and the single-use pairing code from the Android app, plus fallback symbol/timeframe inputs (supported labels: M1, M5, M15, M30, H1, H4, D1). START now validates and applies the nested remote `symbols[]`, `timeframes[]`, `risk_percent`, `max_daily_loss_percent`, and `max_concurrent_positions`; those input lists are only initial/fallback selections. Before entering RUNNING, every requested symbol/timeframe must be selectable, have fresh quotes and recent bars, at least 50 bars of history, and the terminal/account trade permissions must be enabled. The EA claims the terminal using actual account login/server/company/currency. It never accepts broker credentials or API keys.
5. Once paired and online, issue START from the app. The EA requires an accepted heartbeat and fresh authenticated bridge communication before active scanning; command polling and heartbeat cadence are 5 seconds. The initial state is READY; STOP, PAUSE, and EMERGENCY_STOP prevent new entries only and do **not** close positions or alter broker-side SL/TP. RESUME re-enables scanning only after terminal permission checks.

The terminal bearer token is stored in `MQL5/Files/DestinedFX_terminal_token.txt` and command cursor/processed IDs in adjacent EA files. Treat the terminal data directory as sensitive. Do not share these files. On an authenticated HTTP 401/403, the EA immediately enters STOPPED, clears its in-memory bearer token, deletes the persisted token file, and does not scan or trade. To resume after revocation, provide a fresh pairing code and reinitialize/re-pair the EA; it will not silently retry pairing while stopped. If no heartbeat is accepted for 15 seconds (UTC, matching `HEARTBEAT_STALE_SECONDS=15`), it automatically enters STOPPED without liquidating existing positions. Successful command polling alone does not extend this heartbeat lease. No new entries are permitted while heartbeats are stale. The last accepted heartbeat time is tracked in UTC; state and `last_error` are retained locally for the next heartbeat/report.

## Risk and operation

Inputs default to 0.25% per-trade risk, 2% daily loss, and two EA-owned concurrent positions. The Android app also defaults to 0.25% per-trade risk. START validates and applies the phone's runtime instrument/timeframe and risk-limit configuration; the risk percentage must be finite, greater than zero, and no more than the hard 1% cap. Invalid risk/limits are rejected rather than clamped. Sizing uses `min(balance,equity)`, broker-valid volume steps with downward rounding, `OrderCalcProfit` at stop and target, `OrderCalcMargin`, a 10% margin buffer, and a 2.0R minimum. The daily stop blocks additional entries; the EA does not liquidate existing positions. Orders are checked against `CTrade` return status, `ResultRetcode`, and nonzero `ResultDeal` for completed/partial fills (a PLACED response is reported as ORDER_ACCEPTED, not proof of a fill). Heartbeat `last_signal` is a structured object with state, market, prices, risk, rationale and known order identifiers; WAIT includes the latest no-setup reason. Processed command IDs and their original outcome/message are persisted so retry acknowledgements remain truthful. Do not assume broker-specific commission is included in pre-trade loss sizing; actual risk may differ due to slippage, gaps, execution costs, and conversion behavior.

## Known limitations and verification

The bridge must implement the exact v1 endpoints and heartbeat schema in `docs/mt5-bridge-protocol.md`; the EA does not contain a bridge server. MQL5 `WebRequest` must be enabled manually by allowlisting the exact bridge URL; it is unavailable in the MT5 Strategy Tester, so automated Strategy Tester runs cannot validate bridge behavior. It can also fail when MT5 is offline or the server certificate/URL is invalid. Manual terminal testing on a demo account is still required. Command polling and acknowledgements are at-least-once at the HTTP layer; processed command IDs/cursor are persisted locally. Signal dedupe keys are persisted in an account-login-scoped terminal file and reloaded at startup (the latest 1,000 keys); order submission ambiguity on connection loss requires operator inspection before restarting. Multi-terminal duplicate execution is not coordinated by this EA.

A MetaEditor/MQL5 compiler is not available in this environment, so compilation and live broker integration could not be verified here. Review/compile in the target MetaEditor, test every action and heartbeat against the deployed bridge, and run demo-forward tests before live use. This source is supplied as implementation code, not a guarantee of production readiness or investment advice.
