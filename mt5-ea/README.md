# DestinedFX MT5 EA (bridge v1)

`DestinedFXTraderEA.mq5` is a deterministic MQL5 Expert Advisor that scans configured symbol/timeframe pairs and relays authenticated telemetry and commands through the DestinedFX bridge. It supports all eight registered strategy identifiers: SMC confluence, ICT Silver Bullet, Wyckoff schematics, supply and demand, breakout momentum, mean reversion, trend following, and liquidity stop hunts. Each strategy has a closed-candle setup path; indicators and setup data are read from completed bars rather than the forming candle.

## Safety gates

The EA is fail-closed. It requires the expected account login, exact server, and DEMO/LIVE mode to match the attached terminal before claim, START, RESUME, and every order. It requires an accepted authenticated heartbeat, terminal/broker trading permission, fresh quotes, valid broker stops, a hard maximum of 1% risk per trade, and a configurable daily-loss limit no greater than 2%. It never enables LIVE trading by itself and does not liquidate positions when STOP, PAUSE, or EMERGENCY_STOP is issued.

Before each new order, the EA requests a symbol-specific news verdict from the authenticated bridge. Unknown, malformed, uncovered, stale, provider-failure, incomplete, or relevant high-impact verdicts block the order. Effective verdict freshness is the lower of the configured `InpNewsFreshnessSeconds`, the bridge-provided age, and 120 seconds. EA-owned pending orders are cancelled when the current symbol verdict becomes unsafe.

Sizing requires verified positive round-turn costs. For `CONFIGURED_ROUND_TURN`, enter the broker-supported all-in cost per lot for the intended holding period, including round-turn commission, separate fees, and a defensible swap/holding-cost allowance where applicable; `InpCostEvidence` must identify the evidence. `CONFIGURED_PER_SIDE` doubles the verified per-side value. `OBSERVED_ROUND_TURN` groups the last 30 days of matching-symbol history by position ID, accepts only fully closed positions with matched entered/exited volume, and estimates charges from absolute commission, separate fees, and swap per entered lot; it requires at least three qualifying positions and fails closed if costs are missing or zero. A fresh DEMO account usually lacks the history needed for the observed model, so the first DEMO test must use a broker-documented `CONFIGURED_ROUND_TURN` cost and evidence or the EA will correctly refuse to trade. `InpSlippageAllowancePoints` defaults to 20 points and adds a two-leg allowance calculated from the broker's profit model; set it to a conservative broker/symbol-appropriate value. The net 2R rule is `gross reward - all-in costs >= 2 × (gross stop loss + all-in costs)`, so the target requires `gross reward >= 2 × gross stop loss + 3 × all-in costs`. The same cost budget is used for volume sizing and final broker-profit validation after tick rounding. Gaps, execution slippage beyond the configured allowance, and future costs can still exceed estimates; this estimate is not a guarantee.

Volume scaling is disabled by default and cannot exceed the initial volume unless scaling is explicitly enabled and at least the configured minimum of 20 fully closed, reconciled positions qualify. Qualifying history must belong to this EA magic number, contain matching entry and exit deals for the same position, contain no unresolved/open remainder, and have positive aggregate after-cost P/L including commission, swap, and fees. Manual trades, other EAs, duplicate deal records, partial/unresolved positions, and losing histories do not qualify.

## Installation and DEMO verification

Copy the `.mq5` file into the terminal `MQL5/Experts` directory and compile it in the target MetaEditor. Add the exact HTTPS bridge origin under **Tools → Options → Expert Advisors → Allow WebRequest**, set the expected account identity and pairing code, enable Algo Trading, and begin with a broker DEMO account. Confirm broker symbol suffixes, contract specifications, stop/freeze restrictions, and the deployed authorized news provider. The Android app and bridge keep DEMO and LIVE pairings and report files account-scoped.

The EA stores its terminal token, command cursor, processed command acknowledgements, order state, and signal deduplication state persisted in an account-login-scoped terminal file under the MT5 data directory. Treat those files as sensitive. A revoked token or stale heartbeat fails closed and requires operator intervention.

## Verification limitations

MQL5 MetaEditor and a live broker terminal are not available in this Linux development environment. Source-contract and bridge tests do not substitute for genuine MetaEditor compilation, MT5 WebRequest allowlisting, authorized news-provider deployment, or broker DEMO acceptance. Before any LIVE consideration, perform the acceptance runbook with real broker DEMO fills, reconcile partial and final closures, inspect the generated Android PDFs, and retain broker evidence.


## First DEMO-trade acceptance checklist

1. Build the phone APK with the deployed bridge's public HTTPS origin configured. If MT5_MANAGED_SERVICE_URL is absent, the APK deliberately embeds a configuration-required placeholder and managed trading will not connect.
2. Configure CREDENTIALS_FERNET_KEY, a strong WORKER_TOKEN, and BRIDGE_BASE_URL on the bridge. Deploy the authorized economic-news provider and validate each target symbol against its coverage and freshness contract. Do not copy secrets into the Android APK or repository.
3. Provision a dedicated broker DEMO master account, run the managed Windows worker, compile this EA with MetaEditor on the target MT5 installation, and add the exact HTTPS bridge origin to MT5 WebRequest allowlisting. Verify the broker login, exact server, and DEMO mode on the terminal and app agree.
4. Before START, choose a broker-documented CONFIGURED_ROUND_TURN cost with evidence or confirm that OBSERVED_ROUND_TURN has at least three complete, representative closed positions for each symbol. A new demo account normally does not; the EA must block trading when costs cannot be verified. Keep scaling disabled, initial and maximum volume at 0.01, and risk at or below 0.25% for initial acceptance.
5. Confirm the bridge reports READY with a fresh authenticated terminal heartbeat, account identity verified, worker READY, trade permission enabled, and a fresh CLEAR news verdict for every configured symbol. Unknown or unavailable news must block START or orders.
6. Start on DEMO only. Wait for a verified broker order and fill, then compare the broker's deal history with app telemetry. Confirm actual entry/time, executed volume, broker SL/TP, commission, swap/fees, position status and the configured net 2R estimate. Do not treat an order-submitted status as a confirmed fill.
7. Exercise partial closure and final closure only in a controlled DEMO procedure. Confirm that report sync creates an OPEN/fill report and a separate final CLOSED report, and that exit prices, volumes, costs, and net P/L match broker history. Check UNAVAILABLE fields instead of treating them as zero.
8. If any discrepancy appears, issue STOP to prevent new entries, preserve broker evidence and logs, and fix the defect before repeating DEMO. STOP does not liquidate existing positions; broker-managed SL/TP continue to apply. Keep LIVE authorization unused until an independent review of the complete DEMO evidence.
