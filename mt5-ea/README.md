# DestinedFX MT5 EA (bridge v1)

`DestinedFXTraderEA.mq5` is a deterministic MQL5 Expert Advisor that scans configured symbol/timeframe pairs and relays authenticated telemetry and commands through the DestinedFX bridge. It supports all eight registered strategy identifiers: SMC confluence, ICT Silver Bullet, Wyckoff schematics, supply and demand, breakout momentum, mean reversion, trend following, and liquidity stop hunts. Each strategy has a closed-candle setup path; indicators and setup data are read from completed bars rather than the forming candle.

## Safety gates

The EA is fail-closed. It requires the expected account login, exact server, and DEMO/LIVE mode to match the attached terminal before claim, START, RESUME, every order, and every destructive command. It requires an accepted authenticated heartbeat, terminal/broker trading permission, fresh quotes, valid broker stops, a hard maximum of 1% risk per trade, and a configurable daily-loss limit no greater than 2%. It never enables LIVE trading by itself. STOP and EMERGENCY_STOP stop scanning, persist a Bot close-out intent, cancel DestinedFX-owned pending orders and close DestinedFX-owned positions, then retry unresolved exposure on subsequent timer cycles until zero Bot-owned exposure is confirmed. Manual and other-EA trades are not closed.

The bridge's explicit destructive commands are selected pending-order cancellation, cancellation of only snapshot-confirmed EA-magic pending orders, selected position closure, and close-all after a short-lived explicit confirmation. Every target is an exact canonical ticket/position ID and is checked against the live terminal immediately before the operation. Results are per-item, persisted with the request ID, and remain unresolved until a fresh order/position snapshot or broker deal history reconciles the requested change. A partial close is not a fully closed position; any remaining volume and its broker-side SL/TP must remain visible. These operations are not compiler- or broker-verified by static source tests.

Before each new order, the EA requests a symbol-specific news verdict from the authenticated bridge. Unknown, malformed, uncovered, stale, provider-failure, incomplete, or relevant high-impact verdicts block the order. Effective verdict freshness is the lower of the configured `InpNewsFreshnessSeconds`, the bridge-provided age, and 120 seconds. EA-owned pending orders are cancelled when the current symbol verdict becomes unsafe.

Sizing requires verified positive round-turn costs. For `CONFIGURED_ROUND_TURN`, enter the broker-supported all-in cost per lot for the intended holding period, including round-turn commission, separate fees, and a defensible swap/holding-cost allowance where applicable; `InpCostEvidence` must identify the evidence. `CONFIGURED_PER_SIDE` doubles the verified per-side value. `OBSERVED_ROUND_TURN` groups the last 30 days of matching-symbol history for this EA magic number by position ID, accepts only fully closed positions with matched entered/exited volume, and estimates charges from absolute commission, separate fees, and swap per entered lot; it requires at least three qualifying positions and fails closed if costs are missing or zero. A fresh DEMO account usually lacks the history needed for the observed model, so the first DEMO test must use a broker-documented `CONFIGURED_ROUND_TURN` cost and evidence or the EA will correctly refuse to trade. `InpSlippageAllowancePoints` defaults to 20 points and adds a two-leg allowance calculated from the broker's profit model; set it to a conservative broker/symbol-appropriate value. The net 2R rule is `gross reward - all-in costs >= 2 × (gross stop loss + all-in costs)`, so the target requires `gross reward >= 2 × gross stop loss + 3 × all-in costs`. The same cost budget is used for volume sizing and final broker-profit validation after tick rounding. Gaps, execution slippage beyond the configured allowance, and future costs can still exceed estimates; this estimate is not a guarantee.

Volume scaling is disabled by default and cannot exceed the initial volume unless scaling is explicitly enabled and at least the configured minimum of 20 fully closed, reconciled positions qualify. Qualifying history must belong to this EA magic number, contain matching entry and exit deals for the same position, contain no unresolved/open remainder, and have positive aggregate after-cost P/L including commission, swap, and fees. Manual trades, other EAs, duplicate deal records, partial/unresolved positions, and losing histories do not qualify.

## Installation and DEMO verification

Copy the `.mq5` file into the terminal `MQL5/Experts` directory and compile it in the target MetaEditor. Add the exact HTTPS bridge origin under **Tools → Options → Expert Advisors → Allow WebRequest**, set the expected account identity and pairing code, enable Algo Trading, and begin with a broker DEMO account. Confirm broker symbol suffixes, contract specifications, stop/freeze restrictions, and the deployed authorized news provider. The Android app and bridge keep DEMO and LIVE pairings and report files account-scoped.

The EA stores its terminal token, command cursor, processed command acknowledgements, destructive-operation request state, order state, and signal deduplication state in account-scoped terminal files under the MT5 data directory. Treat those files as sensitive. A revoked token or stale heartbeat fails closed and requires operator intervention. If local persistence fails, the EA must not begin a destructive broker call; after interruption it reconciles the original request before any retry, never blindly repeating a close or cancel.

## Verification limitations

MQL5 MetaEditor and a live broker terminal are not available in this Linux development environment. Source-contract and bridge tests do not substitute for genuine MetaEditor compilation, MT5 WebRequest allowlisting, authorized news-provider deployment, or broker DEMO acceptance. Before any LIVE consideration, perform the acceptance runbook with real broker DEMO fills, reconcile partial and final closures, inspect the generated Android PDFs, and retain broker evidence.




Closed-trade history includes actual entry price and broker-server entry time where available. Entry-side commission, fees and any entry-side swap are allocated across close deals by exited-volume share, so the final report aggregates entry and exit charges once. If matching entry history or volume reconciliation is incomplete, commission/fee fields remain unavailable and net P/L is reported as UNAVAILABLE rather than fabricating zero costs.

## First DEMO-trade acceptance checklist

1. Build the phone APK with the deployed bridge's public HTTPS origin configured. If MT5_MANAGED_SERVICE_URL is absent, the APK deliberately embeds a configuration-required placeholder and managed trading will not connect.
2. Configure CREDENTIALS_FERNET_KEY, a strong WORKER_TOKEN, and BRIDGE_BASE_URL on the bridge. Deploy the authorized economic-news provider and validate each target symbol against its coverage and freshness contract. Do not copy secrets into the Android APK or repository.
3. Provision a dedicated broker DEMO master account and deploy the MT5 terminal using one of the documented host paths: the persistent per-pairing Ubuntu runtime in scripts/linux-host/README.md, or the separate Windows owner-worker in managed-worker/windows/OWNER-SETUP.md. Compile this EA with genuine MetaEditor on the target MT5 installation and add the exact HTTPS Bridge origin to MT5 WebRequest allowlisting. Verify the broker login, exact server, and DEMO mode on the terminal and app agree.
4. Before START, choose a broker-documented CONFIGURED_ROUND_TURN cost with evidence or confirm that OBSERVED_ROUND_TURN has at least three complete, representative closed positions for each symbol. A new demo account normally does not; the EA must block trading when costs cannot be verified. Keep scaling disabled, initial and maximum volume at 0.01, and risk at or below 0.25% for initial acceptance.
5. Confirm the bridge reports READY with a fresh authenticated terminal heartbeat, account identity verified, worker READY, trade permission enabled, and a fresh CLEAR news verdict for every configured symbol. Unknown or unavailable news must block START or orders.
6. Start on DEMO only. Wait for a verified broker order and fill, then compare the broker's deal history with app telemetry. Confirm actual entry/time, executed volume, broker SL/TP, commission, swap/fees, position status and the configured net 2R estimate. Do not treat an order-submitted status as a confirmed fill.
7. Test each new cancel/close command only in a controlled DEMO procedure: selected order, EA-managed pending-order bulk cancellation, selected position, explicit close-all confirmation, cancellation/close broker rejection, partial closure, and timeout/restart reconciliation. Confirm exact tickets, per-item outcomes, remaining volumes, and order/deal history. Do not regard an HTTP response, EA retcode, or queued state as final broker confirmation.
8. Exercise partial closure and final closure only in a controlled DEMO procedure. Confirm that report sync creates an OPEN/fill report and a separate final CLOSED report, and that exit prices, volumes, costs, and net P/L match broker history. Check UNAVAILABLE fields instead of treating them as zero.
9. If any discrepancy appears, issue STOP, preserve broker evidence and logs, and fix the defect before repeating DEMO. STOP blocks new entries and retries closing all DestinedFX-owned positions and pending orders; verify a fresh MT5 snapshot confirms STOPPED and zero Bot-owned exposure. Manual and other-EA trades are not touched. Keep LIVE authorization unused until an independent review of the complete DEMO evidence.


### Daily risk guard — MT5 EA enforcement

The managed MT5 EA calculates daily bot-owned net P&L in broker-server time, including closed deal profit, commissions and fees plus current bot-managed floating profit and swap. It emits one-time 80% and 90% terminal push warnings when MetaTrader push notifications are configured. At 100%, it persists an account/server/magic/day-scoped lock, blocks START/RESUME and new orders, cancels only EA-magic pending orders, and closes only EA-magic positions. It verifies each action against refreshed broker order/position state and reports EXIT_PENDING when any outcome remains unresolved. This code path still requires genuine MetaEditor compilation and DEMO terminal acceptance; it is not a universal guard for Deriv or non-MT5 adapters.
## Independent token-free Analyzer market feed

`AnalyzerMarketFeedEA.mq5` is a second, read-only Expert Advisor. It is separate from `DestinedFXTraderEA.mq5`: it has no pairing code, broker password, Bot app token, order placement, or position-management functions. It reads the actual terminal's Market Watch symbols and `SymbolInfoTick` BID/ASK values, then copies completed `MqlRates` candles for the selected symbol. The Android Analyzer reads this separate market-data stream and displays exact BID and ASK using the broker's digits; it does not use TradingView or OANDA.

The host bridge keeps only a short-lived in-memory feed. A missing or older-than-15-second terminal heartbeat clears the available prices and returns `MT5 not connected`; it does not substitute a synthetic price, account snapshot, TradingView, or another broker's quote. Quotes and candles are read-only data and never enter the Bot order command queue.

### One-time terminal setup

1. Build/launch the bridge host and configure the same external HTTPS host origin in the Android app (the existing managed MT5 service URL setting). This is only the market-data host address; it is not a Bot broker profile or a Bot pairing token.
2. In the MT5 terminal, open **Tools → Options → Expert Advisors** and add the exact local feed URL to **Allow WebRequest for listed URL**:
   - Codespaces/Wine when the terminal and Bridge share the Codespace: `http://127.0.0.1:8000`
   - Owner Linux host using the owner Docker network: `http://172.30.250.3:8000`
3. Attach `AnalyzerMarketFeedEA` to a chart and enable Algo Trading / allow WebRequest. The EA is read-only; no broker login is stored or submitted by the Analyzer phone UI. Keep the relevant instrument visible in Market Watch. The EA initially uses the chart symbol/timeframe, then follows the symbol/timeframe selected in the Android Analyzer.
4. Open Analyzer on the phone. It polls the read-only HTTPS market-state endpoint; the local MT5 EA publishes every two seconds. Check that BID, ASK, and the candle chart update from the connected terminal. If terminal heartbeats stop, the UI shows `MT5 not connected`.

The EA source and `.ex5` are compiled and installed by the existing MT5 MetaEditor installation/finalization scripts. The owner must still complete the one-time MT5 WebRequest allow-list and attach the EA to a chart. The owner terminal must be online and logged in to a broker account; the Analyzer phone UI itself does not need a Bot pairing token or a second broker login. CI MetaEditor compilation proves source compilation only, not that an owner's broker terminal is online or that HFM, Exness, FBS, or Deriv has supplied a live quote. The Analyzer's terminal symbol list is the broker's own Market Watch, including broker suffixes and named synthetic indices; a symbol absent from that broker terminal is not fabricated.
